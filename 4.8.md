**Question 8:**
Assume the relation schema $R(A, B, C, D, E, F, G)$ and the set of functional dependencies:
$F = \{ BCD \to A, \ BC \to E, \ A \to F, \ F \to G, \ C \to D, \ A \to G, \ A \to B \}$

**a) Decompose the relation R up to 3NF. Explain all steps.**

**Step 1: Find a Minimal Cover ($F_c$)**
To decompose into 3NF, we first simplify the set of functional dependencies.
1.  **Decompose RHS:** All dependencies already have single attributes on the right side.
2.  **Remove Extraneous Attributes (LHS):**
    *   Look at $BCD \to A$. Check if $D$ is extraneous.
    *   We know $C \to D$. Therefore, the attribute $D$ is functionally determined by $C$.
    *   Since $BC$ determines $C$, $BC$ also determines $D$.
    *   Thus, $BCD \to A$ can be reduced to **$BC \to A$**.
3.  **Remove Redundant FDs:**
    *   Look at $A \to G$. Since $A \to F$ and $F \to G$ exist, $A \to G$ is implied by transitivity ($A \to F \to G$). It is redundant. **Remove it.**
    *   Check $BC \to A$. Is it redundant given others? No, only $BCD \to A$ (now $BC \to A$) implies it.
    *   Check $A \to B$. Redundant? No.

**Minimal Cover ($F_c$):**
$$F_c = \{ BC \to A, \ BC \to E, \ C \to D, \ A \to F, \ F \to G, \ A \to B \}$$

**Step 2: Find Candidate Keys**
*   Let's compute the closure of $BC$:
    *   $BC \to A$ (adds $A$)
    *   $BC \to E$ (adds $E$)
    *   $A \to F$ (adds $F$)
    *   $F \to G$ (adds $G$)
    *   $C \to D$ (adds $D$)
    *   Closure = $\{A, B, C, D, E, F, G\}$.
*   Therefore, **$BC$** is a Candidate Key.

**Step 3: Synthesize 3NF Relations**
For each dependency in the Minimal Cover, we create a relation schema.
1.  $BC \to A \Rightarrow R_1(A, B, C)$
2.  $BC \to E \Rightarrow R_2(B, C, E)$
3.  $C \to D \Rightarrow R_3(C, D)$
4.  $A \to F \Rightarrow R_4(A, F)$
5.  $F \to G \Rightarrow R_5(F, G)$
6.  $A \to B \Rightarrow R_6(A, B)$

**Step 4: Merge Relations**
*   $R_6(A, B)$ is contained in $R_1(A, B, C)$. Discard $R_6$.
*   $R_1(A, B, C)$ and $R_2(B, C, E)$ share the key $BC$. We can merge them into $R_{12}(A, B, C, E)$.
    *   Key for $R_{12}$ is $BC$.
*   $R_4(A, F)$ and $R_5(F, G)$: If we merge these into $(A, F, G)$, the key is $A$. However, $F \to G$ would violate 3NF in that merged table (because $F$ is not a key and $G$ is non-prime). Therefore, we must keep them separate to preserve 3NF.
*   Check if Candidate Key $BC$ is present: Yes, it is in $R_{12}$.

**Final 3NF Decomposition:**
1.  **$R_{ABCE}(A, B, C, E)$**
2.  **$R_{CD}(C, D)$**
3.  **$R_{AF}(A, F)$**
4.  **$R_{FG}(F, G)$**

---

**b) Is this decomposition in BCNF? State the reason.**

**Answer:** No, the decomposition is not in BCNF.

**Reason:**
For a decomposition to be in BCNF, for every non-trivial functional dependency $X \to Y$ in every relation, $X$ must be a **Superkey**.

Let's check the relation **$R_{ABCE}(A, B, C, E)$**:
*   It contains the functional dependency **$A \to B$** (derived from the minimal cover).
*   The candidate key for $R_{ABCE}$ is **$BC$**.
*   Is $A$ a superkey? The closure of $\{A\}$ in this relation is just $\{A, B\}$. It does not determine $C$ or $E$.
*   Since the Left-Hand Side ($A$) of $A \to B$ is not a superkey, this relation violates BCNF.

(Note: The other relations $R_{CD}$, $R_{AF}$, and $R_{FG}$ are in BCNF, but the decomposition as a whole is not because $R_{ABCE}$ is not.)
