

**Question 2: Reasons for using a memory hierarchy, including what data and for how long each level is used.**

**Reasons for Using a Memory Hierarchy:**

1. **Trade-off between speed, cost, and capacity:**  
   Faster memory (e.g., CPU caches) is more expensive and smaller, while slower memory (e.g., hard disks) is cheaper and larger. The hierarchy balances performance and cost.

2. **Locality of reference:**  
   Programs tend to access a small portion of data repeatedly (temporal locality) and data located near recently accessed data (spatial locality). The hierarchy exploits this by keeping frequently/recently used data in faster memory.

3. **Efficient resource utilization:**  
   By organizing storage in layers, the system can provide the illusion of large, fast memory without the prohibitive cost of building entire storage from high-speed components.

---

**Memory Hierarchy Levels, Typical Data Stored, and Retention Duration:**

| Level               | Speed & Cost                        | Typical Data Stored                                                                                          | Retention Time                                     |
|---------------------|-------------------------------------|--------------------------------------------------------------------------------------------------------------|----------------------------------------------------|
| **CPU Registers**   | Fastest, most expensive             | Operands and addresses of currently executing instructions.                                                   | Nanoseconds to microseconds (per CPU cycle).       |
| **Cache (L1/L2/L3)**| Very fast, expensive                | Frequently accessed instructions and data (cached from RAM).                                                  | Milliseconds to seconds (while processes are active). |
| **Main Memory (RAM)**| Fast, moderate cost                 | Running operating system, applications, and active data.                                                      | Seconds to hours (until power-off or process ends). |
| **Secondary Storage (SSD/HDD)**| Slow, inexpensive              | Operating system files, installed software, databases, documents.                                              | Days to years (persistent until deleted).           |
| **Tertiary Storage (Tapes/Cloud)**| Very slow, very inexpensive  | Archives, backups, historical data, rarely accessed bulk data.                                                | Months to decades (long-term retention).            |

---

**Summary:**  
Data moves through the hierarchy based on usage patterns: actively processed data resides in registers/cache, currently running programs and their data are in RAM, while long-term persistent data is stored on secondary/tertiary storage. This layered approach optimizes overall system performance, cost, and capacity.
